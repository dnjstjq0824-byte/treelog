# BACKUP_RECOVERY.md — 백업 주기, 보존 정책 및 재해 복구(DR) 절차서

## 1. 저장소별 백업 및 RPO / RTO 목표
| 데이터 저장소 | 백업 방식 및 주기 | 보존 기간 | 목표 RPO (최대 데이터 유실) | 목표 RTO (복구 소요 시간) |
| :--- | :--- | :--- | :--- | :--- |
| **PostgreSQL 16 (원본 DB)** | 일 1회 전체 베이스 백업 + 실시간 WAL 아카이빙 (PITR) + 동기식 Standby 복제 | 일반 35일, 회계/감사 스냅샷 5년 | **< 1분** (동기 Standby 페일오버 시 **0초**) | **< 15분** |
| **S3 미디어 스토리지** | 오브젝트 버전 관리(Versioning) + 타 리전 비동기 복제(CRR) | 삭제 마커 후 30일 유예 | **< 5분** | **< 10분** |
| **OpenSearch 2.x** | 일 1회 스냅샷 + PostgreSQL 원본으로부터 언제든 100% 재색인 가능 | 14일 | **0 (PostgreSQL 원본 보유)** | 스냅샷 복원 **< 20분** |
| **Redis 7.x** | AOF (`appendfsync everysec`) + 6시간 RDB 스냅샷 | 7일 | < 5초 | < 5분 |
