# PROJECT_OVERVIEW.md — TreeBlog 프로젝트 총괄 헌장

## 1. 배경 및 목적
글로벌 블로그 시장은 크게 네 가지 패러다임으로 분화되어 있다.
1. **Google Blogger**: 구글 계정 기반의 즉각적인 블로그 개설과 손쉬운 무료 서브도메인/커스텀 도메인 연결을 제공하나, 에디터 경험과 커뮤니티 기능이 노후화되어 있다.
2. **Tistory**: 스킨 HTML/CSS 커스터마이징과 개인 도메인 연결, 광고 수익 연동에서 높은 자유도를 제공하나, 초기 설정 장벽이 높고 글로벌 다국어/현대적 블록 에디터 경험이 부족하다.
3. **Naver Blog**: 이웃·서로이웃·공감·댓글 중심의 강력한 커뮤니티 리텐션과 친숙한 에디터(SmartEditor ONE)를 갖추고 있으나, 폐쇄적인 플랫폼 구조로 인해 독립 도메인 연결, 외부 검색엔진 최적화(Global SEO), 원본 콘텐츠 이동성(Portability)에 제약이 있다.
4. **WordPress**: 막강한 SEO와 플러그인 확장성, 데이터 소유권을 제공하나, 호스팅·보안 패치·성능 최적화를 사용자가 직접 관리해야 하거나 관리형 서비스의 비용이 높다.

**TreeBlog**는 위 네 플랫폼의 핵심 강점을 하나의 일관된 아키텍처로 통합하여, **누구나 30초 만에 개설할 수 있으면서도(Blogger), 블록 에디터와 이웃 커뮤니티로 활발히 소통하고(Naver Blog), 커스텀 도메인과 테마로 브랜드 아이덴티티를 구축하며(Tistory), 글로벌 표준 SEO와 데이터 이동성 및 자체 수익화 생태계를 누리는(WordPress/Substack/Medium)** 차세대 글로벌 독립 블로그 플랫폼을 구축하는 프로젝트이다.

## 2. 10대 서비스 도메인 정의 (제0조 구현 명세)

| 번호 | 서비스 영역 | 핵심 제공 가치 및 기술적 구현 목표 |
| :--- | :--- | :--- |
| **1** | **개인 블로그 플랫폼** | 1인 다중 블로그 개설(최대 5개 기본 지원), 직관적인 글쓰기, 모바일 완벽 대응, 사진/일상/리뷰 아카이빙 |
| **2** | **전문 콘텐츠 블로그** | 코드 블록(Shiki 구문 강조), 수식(KaTeX), 표, 목차(TOC) 자동 생성, 시리즈(연재물) 묶음, 리비전 Diff 비교 |
| **3** | **기업·브랜드 블로그** | 팀 블로그 멤버 초대(`OWNER`, `ADMIN`, `EDITOR`, `AUTHOR`, `ANALYST`), 원고 검토·승인 워크플로, 커스텀 도메인 |
| **4** | **커뮤니티형 블로그** | 방명록(Guestbook), 공감(6종 감정 표현 + 기본 좋아요), 계층형 댓글/대댓글, 멘션, 작성자 고정 댓글 |
| **5** | **구독·이웃 시스템** | 팔로우(가벼운 피드 구독), 이웃(단방향 친밀 그룹), 상호이웃(서로이웃 승인 기반 비공개/이웃공개 글 열람), 이메일 뉴스레터 구독 |
| **6** | **독립 도메인형 블로그** | 기본 서브도메인(`{handle}.treeblog.com`), 경로형(`treeblog.com/@{handle}`), 개인 도메인(`CNAME`/`A` + TXT 소유권 검증 + Let's Encrypt 자동 TLS) |
| **7** | **광고·크리에이터 수익화** | 자체 광고 캠페인/슬롯 매칭, 블로거 광고 수익 배분(Revenue Share), 유료 멤버십/단건 유료 글(Paywall), 독자 후원(Tipping), 복식부기 정산 원장 |
| **8** | **콘텐츠 검색·추천** | OpenSearch 기반 다국어 검색, 오타 교정, 자동완성, 시간 감쇠(Time-decay) + 품질 점수 기반 토픽별 인기 글 및 개인화 추천 피드 |
| **9** | **SEO 중심 공개 플랫폼** | Nuxt 3 SSR/Route Caching, 도메인별 동적 `sitemap.xml`/`rss.xml`/`robots.txt`, Canonical 자동 정규화, JSON-LD 구조화 데이터 |
| **10** | **TreeScan 검색 통합** | TreeScan 없이 100% 단독 구동 가능한 독립 플랫폼으로 구축하되, `TreeScan Integration Adapter` 및 Outbox 이벤트를 통해 향후 무중단 연결 |

## 4. 이해관계자 및 사용자 역할 정의

1. **비로그인 방문자 (Anonymous Visitor, `ANON`)**: 공개 게시글 열람, 검색, 카테고리/태그 탐색, RSS 구독, 공개 댓글 열람(정책에 따라).
2. **일반 회원 / 독자 (Registered Reader, `USER`)**: 팔로우, 이웃 신청, 상호이웃 신청, 댓글/대댓글 작성, 공감, 북마크, 유료 멤버십 구독, 후원, 불량 콘텐츠 신고.
3. **개인 블로거 (Blog Owner, `BLOG_OWNER`)**: 블로그 개설, 글 작성/발행, 카테고리/태그 관리, 스킨/도메인 설정, 이웃 관리, 댓글 모더레이션, 통계 열람, 수익 정산 신청.
4. **팀 블로그 멤버 (Team Member)**:
   - `BLOG_ADMIN`: 블로그 삭제/양도를 제외한 모든 설정, 멤버 관리, 도메인/테마 변경, 전체 글 발행/수정.
   - `BLOG_EDITOR`: 모든 구성원의 초안 검토, 수정, 발행 승인, 카테고리 관리.
   - `BLOG_AUTHOR`: 본인 게시글 작성, 수정, 발행(또는 승인 요청), 미디어 업로드.
   - `BLOG_ANALYST`: 방문자 통계, 검색 유입, 수익 리포트 읽기 전용 열람.
5. **광고주 (Advertiser, `ADVERTISER`)**: 광고 계정 생성, 캠페인/예산 설정, 소재 등록, 성과 리포트 확인, 광고비 충전/결제.
6. **플랫폼 운영자 (Platform Admin)**:
   - `SUPPORT_AGENT`: 신고 티켓 1차 검토, 사용자 문의 응대.
   - `TRUST_SAFETY_MOD`: 악성 게시글/댓글 비공개 전환, 스팸 블로그 제재, 이의신청 심사, 저작권(DMCA) 처리.
   - `AD_REVIEWER`: 광고 소재 심사(승인/반려), 부정 클릭 감사.
   - `FINANCE_ADMIN`: 블로거 정산 승인, 지급 보류/환수 처리, 결제 대사(Reconciliation).
   - `SUPER_ADMIN`: 시스템 설정, Feature Flag 제어, 관리자 권한 부여, 감사 로그 열람, 인프라 운영.
